# VIBE 知识视频制作规范（RULES）

> 本文件是 `vibe-video-studio` 项目的唯一制作规范。任何 AI/Agent 制作本项目的视频，必须先完整阅读本文件与 `template/skeleton.html`，再开工。

## 0. 认知对齐

- VIBE 知识视频**不是 AI 文生视频**，而是「代码渲染的 HTML 动画页 + Playwright 逐帧录制 + FFmpeg 合成 MP4」。
- 理由：VIBE 的核心是**画面精确对应讲解内容、字幕逐字同步、信息密度高**，代码渲染才能做到音画 100% 对齐、可反复微调、可批量套模板。
- 技术栈：单文件 HTML（原生 JS + CSS 动画，数据全内联）+ 配音 WAV + 字级时间戳 JSON + Playwright + FFmpeg。

## 1. 硬性铁律（每次制作必须遵守）

1. **音画同步**：所有时间点（场景切换、阶段切换、字幕高亮）都以字级时间戳为唯一来源，杜绝拍脑袋估时间；用 `audio.currentTime` 做全局主时钟（requestAnimationFrame 循环），不用 setTimeout 排事件（会漂移）。
2. **内联数据**：file:// 页面禁止 fetch/XMLHttpRequest 读本地文件，文案、时间戳、场景表必须全部内联进 JS。
3. **id 命名**：JS/CSS/HTML 的元素 id 全部统一用连字符（`s-open`），避免下划线/连字符混用导致找不到元素。
4. **重播清残留**：重播时 startPlay 必须先清除全部场景的 `.active`，否则结束画面叠加在重播画面上。
5. **数字原样**：文案中的数字/数据必须原样呈现，不编造。
6. **文件命名**：素材文案含作品编号与作品名称时，生成文件（HTML、MP4）统一按「作品编号_作品名称」命名（如 `N0003_贝莱斯芽孢杆菌的核心功能之生物防病.html/.mp4`）；无编号时直接用作品名称命名。
7. **分镜头三级时间红线（杜绝伪静态长画面）**：
   - **大镜头切换（Shot）**：单个镜头时长严格控制在 **6 ~ 14 秒**（黄金均值 8~10 秒），**严禁任何单一排版画面持续超过 15 秒**；
   - **镜头内微节拍（Micro-Beat）**：每个镜头内部每 **3 ~ 4 秒**必须规划次级视觉事件（数据打亮、卡片次波弹入、箭头流动、高光呼吸），紧跟配音字词推进；
   - **绝对静止红线**：任意连续 **2.0 秒**画面除字幕外无任何视觉变化即判定为违规，必须补动效。
8. **场景内元素分 2~3 波入场**（badge 弹入 → 标题+副题淡入 → 卡片/数据 stagger 上浮，每项间隔 0.08~0.12s）；关键数字/词条加 breathe/pop 持续强调动效；讲解到具体数据时画面元素同步高亮/放大（字幕-画面联动）。
9. **结尾 CTA**（点赞/关注/收藏/评论）弹入 + 循环脉冲（scale 1→1.06）。结尾内容按文案实际结尾设计：有"下期预告"时用钩子短句；无下期预告时用总结金句或利益点回扣。
10. **音效点缀（双端对齐）**：成片必须有人声外的独立音效轨——转场 whoosh、数字强调 pop、重点强调 ding、结尾 chime、微触击 click。HTML 端内置原生 Web Audio 即时音效引擎（浏览器预览可边看边听，Playwright 录制时自动静音），FFmpeg 端由 `scripts/mux.py` 加载 `assets/sounds/` 真实采样按毫秒精准混入。严禁模型虚构不存在的音频名称。
11. **图数解耦与防重叠排版律（Text-Graphic De-overlap Rule）**：
    - 环形图（SVG Donut/Ring）中心区域**只允许放纯数字+符号**（如 `96%`、`2.33x`），字号严控在 `5.2~5.8cqw`，环内径保留 ≥20px 安全净空；**严禁将描述性多字中文短句塞入圆环内**（指标描述必须移至环外右侧或下方独立的文本信息区）；
    - 柱状图/进度条数值必须与轨道分列排布，严禁浮动覆盖在轨道上方；
    - 卡片内图标必须设置 `flex: none` 与独立的边距间距，严禁绝对定位导致图标覆盖文字。
12. **交付前闭环自动化复核律（Mandatory Pre-delivery Audit Rule）**：
    - 页面生成或修改后，**必须先自动运行 `python vibe.py audit <html_path>` 执行全维度复核门禁扫描**；
    - 检查项包括：图数/图文碰撞重叠（0 穿透）、四边安全区（0 越界）、移动端字号可读性（正文 ≥ 2.8cqw）、竖屏垂直堆叠优先（无挤压左右分栏）、开场黄金 3 秒高频爆点（无呆立 > 1.5s）；
    - **自愈闭环**：若 `audit` 报错，AI 必须自动修复代码并重新复核，直至全项 100% 绿灯（0 违规），方可向用户交付或启动 MP4 渲染！严禁将未经复核的页面交付给用户。
13. **高能粒子背景动效库与学科匹配律（High-Impact Background Particle Rule）**：
    - **严禁全屏使用暗淡稀疏、针尖般低辨识度的微弱粒子**（如以往仅 30 颗 <2px 点粒子，手机上几乎不可见且缺乏生命力）；
    - **必须套用官方高能背景预设库（VibeBackgrounds）**（运行 `python vibe.py bg` 可唤起交互画廊快速预览、调色与提取代码），按科普学科题材精准匹配：
      - `bio-bubbles`（深海微生物细胞浮游光斑，带景深柔焦大光斑与自主升腾）：生物、医药、农业、生防科普首选；
      - `constellation`（神经元能量星图网，带光梭沿线穿梭脉冲）：AI、算法、大模型、脑科学、量子物理首选；
      - `dna-spiral`（双螺旋基因旋转粒子流，双色梯级光芒）：合成生物、基因编辑、育种、分子医学首选；
      - `cyber-grid`（3D 赛博地平透视网格与推进地平线）：工业制造、芯片半导体、算力网络、数据盘点首选；
      - `aurora-dust`（双核极光漫射光球与星尘漂浮）：宏观宇宙、天文航天、自然地理、纪录片首选。
    - 背景层在安全区外亦完整铺满，提供纵深层次感，同时透明度与对比度经过专业光学调校，衬托中区白字大卡片，不喧宾夺主。

## 2. 字幕规范（决定观感）

### 2.1 固定窗口（防止滚动）
- 断句单元**一次性预切分、边界固定不变**，整条常驻显示、只逐字高亮，读完整段才整体切换。
- **严禁滚动/滑动式窗口**：窗口起点或终点不得随当前字动态移动。

### 2.2 短视频断句三原则
- **短**：单行 4~10 字，超 10 字在可断点（标点/虚词）截断；数据/术语不可拆时整段保留（上限 16 字）。
- **整**：只在标点（。！？；，、）或虚词后断，保持意群完整。
- **顺**：下一行从完整语义起点开始，行首若落"的/了/也/就/再"等虚词，把前一行末尾 1~2 字后移。

### 2.3 标点显示规则
- **行末断句标点不显示**：断句点标点（行尾逗号/顿号/冒号）用换行代替，**不渲染**。
- **句末标点显示**：句末标点（。！？等）只在**该句最后一个字幕单元**的末尾显示。
- **单元中间的标点正常显示**（如"产物合成，是一座工厂"中的逗号照常呈现）。

### 2.4 防碎行（硬性）
- 断句切出的单元，**渲染长度（扣除行尾标点）不足 4 字的必须并入前一段**（句首首个单元除外）。禁止出现"促生""防病"这类 1~3 字碎行。
- 实现：buildUnits 末尾追加合并遍历，渲染长度 <4 的单元并入前一段。

## 3. 布局规范（四边安全区 + 三区）

竖屏 cqw/cqh 容器查询单位布局，1080×1920 标准画布。

### 3.1 四边安全区（依据抖音/TikTok 竖屏实测与剪映安全规范）
- **顶部安全区 ≥10cqh（192px，10%）**：状态栏/刘海/平台顶部 UI；
- **底部安全区 ≥14cqh（269px，14%）**：抖音底部按钮/caption 区，字幕底线不得低于此线；
- **左右安全区 ≥8cqw（86px，8%）**：手机圆角/曲面/打孔屏边缘 + 抖音右侧操作栏内沿，左右对称留白；
- **安全区外（四边边缘区域）只允许背景**（粒子/渐变/装饰层），**任何正文/图表/字幕严禁侵入安全区**。
- **制作校对分镜标识特例（Dev HUD）**：分镜编号（`#chapText`，如 `第 1 / 9 节`）属于视频制作与卡点验收阶段的开发辅助标识，实际发布后无须作为正式构图元素。**强制且唯一允许放置于安全区外的左上角盲区（推荐 `top: 3.2cqh; left: 4cqw;`）**，采用极简微透磨砂底衬（字号 `2.0~2.4cqw`，低对比度微透明度）；此设计既便于制作者和测试脚本全流程实时监控镜头推进，又绝不侵占正片安全区与主标题重心，在平台发布后被状态栏自然避让或遮挡。

### 3.2 三区布局（均在安全区内，互不重叠，净空 ≥5cqh）
- **上区（顶部纯粹作品标题区，100% 聚焦主题）**：
  - **顶部安全区内唯一内容**：**安全区可显示区域只显示作品标题**，严禁在安全区内堆叠任何分镜头胶囊标签、小节指示器、进度微标或 HUD 微标！分镜提示已外移至安全区外左上角盲区，确保安全区内顶部 100% 聚焦视频主题与核心 IP。
  - **长短自适应与语义断句规范**：
    - **文字较少（短标题，≤12 字或单意群）**：显示成 **1 行**；居中排布，字号更大更饱满（`4.0 ~ 4.5cqw`），字重 900，单行一目了然；
    - **文字较多（长标题，>12 字或含主副题/复合意群）**：根据**语义自然断句**后显示成 **2 行**（双行标题）：
      - **语义切分铁律**：优先在标点符号处断行（如间隔号“·”、冒号“：”、破折号“——”、逗号或空格）；无标点时在核心主体名词与修饰论述之间断开；严禁孤立单字断行，第二行不得少于 4 字；
      - **层次排版**：第一行为核心主词/IP名（`3.8 ~ 4.2cqw`，字重 900），第二行为副标题/细分维度（`3.2 ~ 3.6cqw`，字重 700），行高紧凑（`1.2 ~ 1.25`），两行间距 `0.6cqw`，垂直总高度 ≤6cqh，与中区保留充足净空（≥5cqh）。
  - **好看与醒目视觉质感标准**：
    - **发光微渐变**：文字采用高质感渐变（高亮冷白微混浅翠绿/浅青蓝），配合 `-webkit-background-clip: text`，杜绝暗淡灰白；
    - **立体多层光晕**：叠加深色硬阴影与微光环境晕染（`filter: drop-shadow(...)` 或 `text-shadow: 0 2px 10px rgba(0,0,0,0.85), 0 0 18px rgba(74,222,128,0.3)`），在任何动态粒子/光斑背景上均极为清晰、不被吞噬；
    - **轻透悬浮微底衬**：标题外部可包裹一层极轻薄通透的悬浮磨砂拟态胶囊底衬（微透暗色 `rgba(14,26,36,0.55)` + `backdrop-filter: blur(8px)` + 1px 微发光边框），增强视觉聚焦度与杂志级大片质感。
  - 用户明确说不显示顶部时，成片只含中区+下区。
- **中区（内容区）**：场景主内容，垂直居中。**内容高度上限 ≈54cqh（1036px）**，超限必须压缩（缩小主图形/收紧网格间距/精简文字行数）；**内容宽度 ≤84cqw（907px，居中 x∈[86,994]）**，多栏网格/横条/横幅卡 ≤82cqw。
- **下区（字幕区）**：卡拉OK字幕，容器 `bottom: 14%`，字幕底线不得低于 14cqh 安全线；字幕容器高度按单行实际行高设定，`min-height` ≤7cqw。
- **三区间隔**：上区底与中区顶、中区底与字幕顶各保持 ≥6cqh 净空，不重叠、不粘连。
- **开场/结尾阶段同样遵守安全区与三区范围**，不得全屏溢出。

### 3.3 顶部大字与开场元素宽度红线
- 开场钩子大字、主题大字、CTA 按钮等元素：`font-size` 按安全宽度反算（单行最长字串 ≤84cqw），并加 `max-width:84cqw` 兜底；实测长字串如"农用菌中的全能选手？"用 8cqw，"农业黑科技·功能菌"用 7.6cqw。

### 3.4 竖屏垂直优先排版律（Vertical Stacking First，核心铁律）
- **空间认知**：抖音 9:16 竖屏高宽比达到 1:1.78，垂直纵向高度充沛（中区可用高度达 51~56cqh），而横向宽度极其宝贵（安全区内宽度上限 82~84cqw）。
- **多条内容强制垂直上下堆叠**：在正文中间区域展示 2~3 条要点、对比卡片、痛点瓶颈或分支机制时，**强制优先采用上下纵向堆叠通栏卡片（`card-stack`，`display: flex; flex-direction: column`）**：
  - **通栏宽度**：统一为 `80 ~ 82cqw`，充分利用横向安全空间；
  - **大字号与易读性**：卡片标题 `3.6 ~ 4.2cqw`（加粗清晰），卡片正文 `2.8 ~ 3.2cqw`（行高 1.4~1.5），大图标 `5.5 ~ 6.8cqw`，严禁正文字号低于 `2.6cqw`；
  - **空间饱满度**：单张堆叠卡高度约 `10 ~ 13cqh`，两卡加间距正好饱满填充 `26 ~ 34cqh`，彻底消除上下大块黑屏留白与空洞感，在手机屏幕上极度舒适清晰。
- **左右分栏布局的降级准入限制**：
  - **严禁**在只有 2 条长描述内容时使用左右小卡片（每列仅 38~39cqw 会导致文字严重折行、字号被迫缩至 2.2cqw，极度拥挤且上下留下大片黑色虚空）；
  - **仅当**上下纵向空间严重不足时（例如同屏已有大尺寸环形图/柱状图占据了 25cqh，下方仅剩 10cqh 无法容纳垂直双卡），或者内容为纯粹的极简微型对比标签（如 4 格微型图标网格、纯数字无长句的对比 `52.2% vs 96.55%`）时，才允许使用左右紧凑布局。

### 3.5 中文精细化排版与防断词铁律（Chinese Typography & Anti-Orphan Rules）
- **标题语义对称断行（Heading Semantic Line-Breaking）**：
  - 严禁让浏览器默认自动折行导致末尾掉出 1~3 个字的“悬挂孤字”（如 `为什么是农用菌中的"全能` / `选手"?`）；
  - 大标题字数 >10 字时，**必须显式根据意群进行语义分行**（添加 `<br>` 或分级子行），保持上下两行字数比例协调（如第一行 4~8 字，第二行 6~10 字）；
  - 核心名词或焦点短语（如 `农用菌中的"全能选手"`）必须作为一个不可分割的整体成行呈现，并辅以高亮/发光。
- **专有名词禁止拆词截断（Anti-Word-Splitting）**：
  - 严禁专有名词跨行被生硬腰斩（如将“脂肪酶”拆成 `脂` 与 `肪酶`、将“革兰氏阳性菌”跨行拆断）；
  - 必须通过结构化单行条目、调整字号行宽或添加 `white-space: nowrap` 意群包裹，保证每一个科学术语与专业词组 100% 完整显示。
- **标签矩阵规整排布（Tag Matrix & No Orphan Chips）**：
  - 多胶囊标签严禁使用 `flex-wrap: wrap` 导致最后一个标签落单下沉居中；
  - 包含因果逻辑的内容必须采用层次化结构（上方诱因居中全宽胶囊 → 下方多列等宽网格并排后果矩阵 `grid-template-columns: repeat(3, 1fr)`），整齐划一、层级分明。
- **图文卡片结构化清单化（Card Structured Bullet Points）**：
  - 避免在左右紧凑分栏的半幅区域塞入连续无断句长文本；
  - 统一采用“左侧紧凑图示/SVG + 右侧结构化条目清单（条目标签 + 单行短语）”，让观众在 1 秒内抓取核心信息，避免长句被挤压折断。

## 4. 开场规则（抖音爆款黄金 3 秒与高频爆点）

- **黄金 3 秒高频爆点铁律（Golden 3-Second Hook Rule）**：
  - 抖音竖屏短视频前 3~5 秒决定 80% 以上用户的停留与完播率。**严禁首屏静态卡片呆立超过 1.5 秒**！
  - **开场必须多阶段递进爆点（Multi-Phase Micro-Beats）**：
    - **第 0.0 ~ 1.5 秒（极速视觉吸睛钩子 Hook Phase）**：画面立即触发高冲击波视效：如雷达波扫描扩散、高能发光光晕、红色/荧光绿警告爆点徽标、大字反差提问（如“野生菌为何难挑大梁？”、“野生原菌无法直接下田？！”）；
    - **第 1.5 ~ 4.0 秒（核心主角强力登场 Slam/Topic Phase）**：画面发生质变或镜头切换！伴随风切音效（Whoosh）与高光转场，核心主角大字强力推入（Punch-in，scale 0.9->1.02），发光粒子聚集；
    - **第 4.0 ~ 7.5 秒（核心矛盾反差 VS Phase）**：切入下一镜头或第一组对比卡片（如野生菌 vs 田间尖兵），形成层层递进的认知冲击。
- **开场镜头时长红线**：
  - 开场镜头（Shot 01）如果在单一阶段内，时长不得超过 4.0 秒；若文案首句较长（如 >6 秒），**必须在 Shot 01 内部设置 `data-phase` 状态机或将其切分为连续的快速转场微镜头**，确保前 3~5 秒内画面至少发生 2 次高能动效推进！
- **开场结构不套模板**，由文案/音频内容决定，常见三种形态：
  1. **钩子开场**：反差数字、悬念提问、痛点场景、强利益点；
  2. **直奔主题**：首句即核心观点，直接呈现主题 + 关键数字/图形；
  3. **系列回顾开场**：仅当文案确实承接上期（含"上期/接上期/接着讲"等）才用回顾卡。
- **每个开场阶段的时间点一律从字级时间戳精确读取，不得估算**；首屏不放纯品牌名/纯标题（品牌名可作辅助元素）。

## 5. 图案化表达（画面不能只剩文字）

- 每个场景必须有**图形化主视觉**：数据用图表（环形/进度条/柱状/块状占比，禁止裸数字），概念用图示（SVG 图标 + 箭头流程图，禁止纯文字卡片），抽象概念用视觉隐喻（武器库=盾牌+子弹、打疫苗=针筒+盾牌、抢地盘=网格占位）。
- 主视觉是画面焦点，文字是配角（文字行数 ≤2 行/屏，不含字幕）。
- **全部图案用内联 SVG 手工绘制**（file:// 页面禁止外链图片/字体），统一线性图标风格 + 主题色系；图形可加描边动画（stroke-dashoffset 画线）、浮动/呼吸/旋转扫描/流光循环动效（同屏 ≤2 种）。
- 每个场景有氛围背景层（渐变+几何装饰+粒子，低透明度不抢戏）。

## 6. 模板 / 配色 / 音效选择决策表

| 文案类型 | 推荐基础模板 | 推荐主题配色 | 动效与视觉组件侧重 | 音效侧重 |
|---|---|---|---|---|
| **讲功能/机理**（促生、防病、作用机制） | `template/skeleton.html` | 绿色农科风 (`var(--green)`) | SVG 环形进度图 + 双列对比卡 + 递进流程链 | pop 数字强调 |
| **讲历史/演进**（技术革命、发现史、大事记） | `template/skeleton-timeline.html` | 深色科技风 (`var(--cyan)`) | 垂直发光时间主轴 + 节点渐进点亮 | whoosh 转场 |
| **讲对比/评测**（双雄对抗、优缺点分析） | `template/skeleton.html` | 科技风或警示风 | 双列对抗分栏卡片 + 环形占比 | whoosh + pop |
| **讲产业化/登记**（历程回顾+产业成果） | `template/skeleton-timeline.html` | 绿色或商业金 | 时间轴 + 徽章 + 数据卡 | whoosh + pop + chime |

- 模板调用策略：**机理科普类文案优先选择 `skeleton.html`，历史演进/大事件类文案优先选择 `skeleton-timeline.html`**。
- 选择方式：**系列级指定**（一个系列一套模板，对话说一次批量生效）> **自动决策**（按上表由 AI 判定）> **对话临时指定**。特殊单期才在素材目录放 manifest 说明。

## 7. 音效契约与语义映射铁律（SFX Standards）

音效是强化短视频微交互（Micro-interactions）的核心手段。任何模型制作视频时，**必须严格遵守以下白名单与映射契约**：

### 7.1 音效白名单（严禁虚构任何未定义音频）
系统中仅允许使用以下 5 款标准音效（物理资源在 `assets/sounds/`，页面 API 为 `VibeSound.play(id)`）：
1. **`whoosh`**（风切转场）：场景切换、镜头平移、全屏卡片滑入（0.35s）。
2. **`pop`**（Q 弹强调）：关键数字跳动、百分比展示、标签浮现、气泡弹窗（0.12s）。
3. **`ding`**（水晶重点）：顿悟转折、核心金句、反差真相、机制突破（0.45s）。
4. **`chime`**（结尾和弦）：收束定格、点赞/关注/CTA 弹入引导（1.10s）。
5. **`click`**（科技微触）：步骤展开、时间轴游标跳动、清单逐项出现（0.05s）。

### 7.2 三层调用与自动绑定机制
- **第 1 层：组件级自动发声（模型零心智负担）**：
  - 骨架模板的 `setScene(idx)` 已经自动绑定 `VibeSound.play('whoosh')`；
  - 骨架模板最后一幕（结尾 CTA）已自动绑定 `VibeSound.play('chime')`；
  - 流水线 `vibe.py pipeline` 未提供 `sfx.json` 时，自动解析场景时间戳挂载 `whoosh` 与 `chime`。
- **第 2 层：标签驱动自动映射（提取阶段）**：
  - 在编写 `timeline.txt` 关键词时，打上通俗业务标签（如 `3.5倍|数据`、`致命痛点|重点`、`关注下期|结尾`）；
  - `scripts/extract_timeline.py` 会自动将标签转为对应的 `pop`、`ding`、`chime` 时间点，导出合规 `sfx.json`。
- **第 3 层：手动微动效精准调用**：
  - 仅在特定数据滚动完毕或高光图形浮现瞬间，可在 JS 动效回调中显式调用 `VibeSound.play('pop')` 或 `VibeSound.play('ding')`；
  - **防暴击红线**：严禁每出现一个字都响一次音效！同场景内 `pop` 不得超过 3 次，两声间隔不得低于 0.6 秒；`ding` 全片仅限 1~3 次最高潮点。

### 7.3 音效听觉调谐与潜意识融合铁律（-15dB 法则与低通暖化）
- **潜意识存在法则（Subconscious Presence Rule）**：
  - 音效是视觉动效的“心理共振伴侣”，其定位是**强化无意识心理预期**，绝非听觉主体；
  - **人声绝对统治**：任何时刻音效的平均响度（RMS）必须低于解说人声 12~18dB（推荐 peak ≤ -16dBFS，RMS ≤ -28dBFS）；**严禁音效响度倒挂或反客为主**。
- **低通暖化过滤（Low-pass Warmth & Anti-Harshness）**：
  - 人耳对 2kHz ~ 6kHz 频段极度敏感，尖锐的正弦波或高频白噪极易造成刺耳烦躁感；
  - 所有 UI 动效发声必须经过低通滤波（Lowpass Filter ≤ 2400Hz），切除刺耳金属毛刺与高频白噪；
  - `whoosh` 偏向 120~820Hz 温润气流推行感，`pop` 采用 480Hz 下潜水滴微触感，`ding` 采用 880+1320Hz 柔和双音编钟感，平滑衰减，听感高级温润。
- **Web Audio 与混音管道双重锁死**：
  - HTML 端 `VibeSound` 网页合成器主增益严格控制在 `0.065 ~ 0.08`，且必须接入 `BiquadFilterNode(lowpass)`；
  - FFmpeg 最终混音管道（`scripts/mux.py`）必须强制声明 `volume=0.12,lowpass=f=2400`，杜绝任何破音或刺耳毛刺。

## 8. 制作流程（六步闭环）

1. **素材**：文案（用户提供）+ 配音 WAV + 字级时间戳 JSON（每字含 StartSeconds/EndSeconds/DurationSeconds/IsVadBoundary）。
2. **时间线提取**：用 `scripts/extract_timeline.py` 从时间戳提取关键句时间点（场景边界、开场相位、音效点），**不估算**。
3. **生成 HTML**：**以 `template/skeleton.html` 为基底修改**（禁止从零手写），数据全部内联；场景映射按分镜头规划切分，落实竖屏垂直堆叠优先与黄金 3 秒开场。
4. **质量复核门禁（Mandatory Audit Gatekeeper）**：运行 `python vibe.py audit <html路径>` 执行全维度碰撞重叠与规范复核；若有报错必须自动修正并复查，直至 100% 绿灯方可交付。
5. **逐帧录制**：用 `scripts/render.py`（Playwright，系统 Python；20fps；时长 >5 分钟分段跑，每段 ≤600 帧）。帧目录用作品子目录的 `_work/frames`。
6. **合成 MP4**：用 `scripts/mux.py`（视频轨 + 人声 + 音效轨 amix），`scripts/verify.py` 验证（ffprobe 规格 + 音效抽点 + 帧数）。成品放 `output/{作品编号_作品名称}/`，中间产物（帧/音效/日志）放该子目录 `_work/`，不污染成品层。

## 10. 环境与命令要点

- 运行前请先执行 `python scripts/doctor.py` 进行环境完整性检测。
- Python 环境：需确保已安装 `playwright` 及其浏览器内核（若存在多 Python 环境，请指定包含 playwright 的 Python 解释器）。
- ffmpeg：gyan.dev 8.x（`ffmpeg -version` 确认存在）。
- 录制/合成都是长任务，时长 >5 分钟分段跑（每段 600 帧）；后台任务被中断时，查最大帧号后从断点续跑。
- MP4 必须 `-pix_fmt yuv420p`（抖音/手机可播）、`-shortest` 对齐音频结束。
- 一键清理还原：制作完毕或需要重置工作区时，执行 `python vibe.py clean`（清理 inputs/output/临时缓存，恢复原始状态）。
