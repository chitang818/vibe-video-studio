# 关键技术细节（决定成败）

## 1. 卡拉OK字幕（逐字高亮 + 固定窗口）

- 驱动：`requestAnimationFrame` 循环读 `audio.currentTime`（音频主时钟，不漂移）。
- 当前字：对 TIMES 二分查找 `TIMES[i] <= t` 的最大 i。
- **固定断句单元（关键，防止滚动）**：一次性预切分全文 ——
  1. 按句末标点（。！？!?；;）分句；
  2. 句内按逗号/顿号（，、）拆子段；
  3. 子段超 10 字时，从后往前在可断点（分隔符或"的地得"虚词，距段首 8~10 字）截断；
  4. 无可断点且整段 ≤16 字时整段保留（数据/术语不可拆）；超 16 字才在 10 字处硬截。
  单元边界预计算后**固定不变**。
- 运行时窗口：查当前字落入哪个固定单元 → **整条常驻显示、只逐字高亮**（已读绿色、当前字发光、未读灰色）；当前字越过单元末尾标点才整体切换到下一单元。
- **禁止滚动式窗口**：窗口起点/终点不得随当前字动态移动（"终点=当前字后第一个分隔符"、"超长时起点前移"都会造成字幕滚动，影响观感）。
- **短视频断句三原则（抖音观看习惯，必须遵守）**：
  - **短**：单行 4~10 字，超 10 字在可断点截断；数据/术语不可拆时整段保留（上限 16 字）。
  - **防碎行**：句内按逗号/顿号拆子段后，**渲染长度不足 4 字的单元必须并入前一个单元**（如"促生、防病、修复"拆出的"促生""防病"2 字单元，并入前段形成 8~10 字行）；禁止出现 1~3 字碎行（句首首个单元除外）。实现：buildUnits 产出后加一遍合并遍历——单元渲染长度（扣除行尾标点）<4 时，把该单元终点并入前一单元。
  - **整**：只在标点（。！？；，、）或虚词之后断，保持意群完整，不在词组中间硬切。
  - **顺**：下一行从完整语义起点开始；若行首是"的 / 了 / 也 / 就 / 再"等虚词，把前一行末尾 1~2 字后移，保证每行开头是实词。
- **标点显示规则（断句不带标点，标点只在句尾）**：
  - **行末断句标点不显示**：断句点（用于分行的逗号/顿号/冒号等，位于单元末尾）用换行代替停顿，**不渲染**——字幕只显示文字内容，不带行尾标点；
  - **句末标点显示**：句末标点（。！？!?；;）只在**该句最后一个字幕单元**的末尾渲染（如"…一座天然抗生素工厂。"，"。"显示）；
  - **单元中间的标点正常显示**：非行尾的标点（如"产物合成，是一座天然抗生素工厂"中位于单元中部的逗号）照常渲染；
  - 实现要点（渲染层）：渲染单元 [a,b] 时先输出 [a, b-1] 全部字符，再判断 CHARS[b]——若是句末标点则输出，若是其他标点（，、：等断句点）则跳过不输出；单元中间标点自然落在 [a, b-1] 内正常显示。断句单元边界（buildUnits）保持不变，仅渲染层按上述规则过滤。

## 2. 场景切换（N 场景时间轴）

- `sceneAt(t)` 返回 `t >= SCENES[i][1]` 的最大索引。
- `setScene(idx)`：移除旧场景 `.active` → 加新场景 `.active` → 强制 reflow。
- **重播时 startPlay 必须先清除全部场景的 active**，否则结束画面会叠加在重播画面上。

## 3. 开场设计（抖音热门规则 · 通用形态）

- 抖音算法核心：**开头 1 秒内画面必须有动效和信息**，静态开场（>2s）会损失停留。
- **开场结构由文案/音频内容决定，不做模板强制**。按文案实际开头识别形态，常见三种：
  - **形态 A · 钩子开场**（最推荐）：文案首段含反差数字/悬念/痛点/强利益点时，把该信息做进首屏——钩子大字冲击入场（scale 0.8→1 + 扫光 + 粒子爆发），首字出声前完成。品牌名/标题作辅助行或移到第 2 屏。
  - **形态 B · 直奔主题**：文案首句即核心观点（无回顾、无铺垫）时，首屏直接呈现主题 + 关键数字/图形，不做多余闪屏。
  - **形态 C · 系列回顾开场**：仅当文案明确承接上期（含"上期/接上期/接着讲/上一期"等措辞）才使用回顾卡（"接着上期・继续往下讲"，回顾卡属中区内容，可带承接说明，**不涉及顶部系列名**）；无此内容时**禁止**强行做"上期回顾"阶段。
- **每个开场阶段的时间点必须从字级时间戳精确读取，不能估算**——无论是单段开场还是多段开场（如 A 形态的"钩子→主题→预告"）。
- 参考样本（系列式作品）：N0002 首字"喽"在 1.87s，开场分"闪屏→回顾→主题→预告"四段，边界 = 1.87 / 7.35 / 14.87 / 16.43s；N0003 类似四段，边界 = 1.87 / 8.07 / 15.27 / 19.64s。**这是系列作品的样本，不是通用模板**。

## 4. 音画同步铁律

- **所有时间点（场景切换、阶段切换、字幕）都以字级时间戳为唯一来源**，杜绝拍脑袋估时间。
- 用 `audio.currentTime` 做全局主时钟，不用 setTimeout 排事件（会漂移）。
- 验证方法：真实播放 + 定点读取（播放中 `a.currentTime = X` 后读 data-phase / 字幕文本）。

## 5. 四边安全区 + 三区布局（安全区铁律）

- 用 cqw/cqh（容器查询单位）做竖屏布局，1080×1920 为标准画布。
- **四边安全区（依据抖音/TikTok 竖屏实测 + 剪映/CapCut 安全规范，数值为 1080×1920 下取值）**：

| 边 | 安全区 | 依据 |
|---|---|---|
| 顶部 | ≥10cqh（192px，10%） | 抖音顶部"关注/推荐"标签 + 手机状态栏/刘海（TikTok 实测顶部 UI 约 150px，刘海另加 50~100px） |
| 底部 | ≥14cqh（269px，14%） | 抖音底部按钮/caption 区（实测单字幕约 250px、双行 caption 可达 422px；Wahlu 实测建议字幕最低行 ≥1709px，即距底 ≤211px 时安全） |
| 左侧 | ≥8cqw（86px，8%） | 手机圆角/曲面/打孔屏边缘裁切；剪映安全区习惯为四边对称留白 |
| 右侧 | ≥8cqw（86px，8%） | 抖音右侧操作栏（点赞/评论/分享竖排，实测约 179px 宽，Kliptools 实测）；8cqw 保证内容避开按钮内沿，剪映/CapCut 建议避开右侧 15~20% 可作更保守取值 |

- **安全区铁律**：安全区范围外（四边边缘区域）**只允许显示背景**（粒子/渐变/装饰层，`pointer-events:none`）；**任何内容——标题、文字、图形、卡片、字幕——一律不得进入安全区**。全部内容必须居中显示在安全区以内：
  - 内容水平范围：居中，左右各留 ≥8cqw → **内容最宽 ≤84cqw**（907px，x ∈ [86, 994]）；
  - 内容垂直范围：顶部 ≥10cqh、底部底线 ≥14cqh（字幕文本底线不得低于 y=1690px 安全线）。
- **中区（内容区）高度推导（1080×1920 标准画布）**：
  - 上区底 = 10cqh(安全区) + 标题行高(≈3.2cqh) ≈ **16cqh（307px）**；
  - 字幕顶 = 1920 − 14cqh(底部安全区) − 字幕行高(≈4.6cqw×1.8≈96px≈5cqh) ≈ **81cqh（1555px）**；
  - 中区可用 = 上区底 + 4cqh间隔 ~ 字幕顶 − 4cqh间隔 = 20cqh ~ 77cqh → **中区内容高度上限 ≈54cqh（1037px）**；
  - **填满纪律（竖屏阅读优先，最重要）**：中区内容必须**尽量占满中带**，目标内容高度 ≥80% 中带（≈43cqh）；**禁止"小内容垂直居中留白"**（小内容一居中，上下各空一大截，画面显小、字显小，这是头号观感问题）。用**放大主图形、放大字号、收紧间隔**去填充，而不是把内容做小居中。仅当内容确实超上限时才压缩（缩小主图形、收紧网格间距、精简文字行数），禁止溢出进安全区或字幕区。
- **内容宽度统一规则（用满宽度）**：
  - 所有场景内容宽度 ≤84cqw（907px，居中）；多栏网格（4 格武器库/4 格病原菌/2 格对比卡）、横条（流程链/时间轴/信号链路）、横幅卡一律 **≤84cqw**；单个大数字/图标 ≤84cqw；
  - **内层图形/卡片/网格目标宽度 80~84cqw，尽量用满内容区；禁止把内容做窄到 70cqw 以下**（窄内容会在两侧造成大留白，加剧"内容显小"）。
  - 实现：`.scene .inner` padding 左右各 8cqw，内容区宽 84cqw，内部元素用容器百分比（90%≈75cqw、100%≈84cqw）或固定 80~84cqw，禁止硬写 88~92cqw 等越界宽度。
- **字号基准（1080×1920 竖屏，任何文字不得低于）**：主标题 h2 ≥5cqw（≈54px）、场景徽标 badge ≥2.8cqw、副题/说明 ≥2.6cqw、卡拉OK字幕 ≥4.6cqw（≈50px）、主数字/钩子 ≥8cqw（≈86px）、图形内标注 ≥2.4cqw。字号能再大就再大，以不溢出、不重叠为界。
- **画面垂直方向固定三个独立区域，三区互不重叠、彼此留足间隔（≥6cqh 净空），不得贴得太近**：

```
┌──────────────────────────┐  ← 顶部安全区 10cqh（仅背景）
│  ▢ 上区（纯粹作品标题区）   │  ← 画面顶部只显示作品标题（无分镜胶囊/无HUD）
│      （长短自适应单/双行） │     （字少单行 4.0~4.5cqw，字多语义断句双行）
│      （默认显示；可整区隐藏）│
├──────────────────────────┤  ← 净空 ≥4~5cqh
│                          │
│   中区（内容区）          │  ← 场景主内容（badge/标题/图形/卡片/数据）
│      尽量占满中带         │     不侵入上区与下区，不超出左右安全区
│                          │
├──────────────────────────┤  ← 净空 ≥4cqh
│  下区（字幕区）           │  ← 卡拉OK字幕，bottom:14%，底线≥14cqh安全线
└──────────────────────────┘  ← 底部安全区 14cqh（仅背景）
   ←左右各 8cqw 安全区（仅背景）→
```

- **上区（标题区，可选）**：
  - 默认显示，内容**只含作品标题**（严禁包含分镜头序号、小节胶囊、进度微标或 HUD）。
  - **长短自适应与语义断句三铁律**：
    ① **字数较少（短标题，≤12字或单意群）**：单行居中排布，字号 `4.0 ~ 4.5cqw`，字重 900；
    ② **文字较多（长标题，>12字或含复合意群）**：根据语义断句拆成 2 行展示（双行标题）。优先在标点符号（`·`、`：`、`——`、空格）或主谓语之间自然断开；主标题行 `3.8 ~ 4.2cqw`，副标题行 `3.2 ~ 3.6cqw`，行高 1.25，两行间距 0.6cqw，总高 ≤6cqh；
    ③ **好看与醒目视觉包装**：采用微发光高亮渐变字色（冷白微渗主题亮色）+ 立体双层阴影光晕（`text-shadow: 0 2px 10px rgba(0,0,0,0.85), 0 0 18px rgba(...)`）+ 悬浮轻透磨砂微底衬（`rgba(14,26,36,0.55)` + 8px 毛玻璃高斯模糊 + 1px 细光边框），高级通透吸睛，绝不与动态背景混杂。
  - **若用户明确说不显示顶部**：上区整块隐藏（HTML 中该容器 `display:none` 或从页面移除），成片只包含中区+下区两部分，不留空标题区、不残留占位。
- **中区（内容区）**：场景主内容（badge / 标题 / 图形 / 卡片 / 数据）**尽量占满中带**（目标高度 ≥80% 中带，禁止小内容垂直居中留白）；内容总高不得超过中区可用高度（中区顶 = 上区底 + 4cqh，中区底 = 字幕顶 - 4cqh，即内容高 ≤54cqh），内容宽度 80~84cqw 居中（不超出左右安全区），逐场景实测不侵入上/下区、不超左右安全区。**开场/结尾阶段（S1 钩子大字/回顾卡/预告网格、S8 CTA）同为中区内容，遵守同样的安全区与高度/宽度约束，不得全屏溢出。**
- **下区（字幕区）**：卡拉OK字幕固定在底部安全区上沿：容器 `bottom: 14%`（相对画面高度，字幕文本底线 ≥14cqh 安全线），不贴底、不遮挡中部主视觉，也避免和抖音底部 UI（点赞/评论栏）重叠；字幕为单行（断句后 ≤10 字，16 字整段时单行仍可容纳），容器 `min-height` 按单行实际行高（4.4cqw × 1.8 ≈ 85px ≈ 4.4cqh）设置，不超过 7cqw，避免虚高占用中区空间。
- **顶部安全区实现**：上区容器 `padding-top: 10cqh`（10cqh = 192px @1080×1920），标题与序号走 flex 纵向堆叠（见上），**不把序号绝对定位到固定 top**；**安全区一律用 cqh（高度单位）/cqw（宽度单位）定位，不要用 px 或百分比混用**，保证不同画幅等比。
- 三区间隔实现：上区容器 `bottom` 与中区容器 `top` 之间、中区容器 `bottom` 与字幕容器 `top` 之间各留 **≥4cqh（约77px @1080×1920）** 净空即可（防重叠即可，间隔过大反而压缩中区、让内容显小）；用容器查询单位保证不同画幅等比。

## 6. 文件命名规范

- 素材文案含作品编号与作品名称时，生成文件（HTML 动画页、MP4）统一按**「作品编号_作品名称」**命名，编号与名称之间用半角下划线连接：如 `N0003_贝莱斯芽孢杆菌的核心功能之生物防病.html` / `N0003_贝莱斯芽孢杆菌的核心功能之生物防病.mp4`。
- 无作品编号时，直接用作品名称命名。
- 作品目录名可用短名（如 `vibe-defense/`），但交付给用户的 HTML / MP4 文件名必须遵循上述规则，方便作品归档与管理。

## 7. 录制与合成命令

HTML 动画页结构要求（自包含单文件）：

```html
<audio id="voice" src="assets/voice.wav" preload="auto"></audio>
<button id="btnPlay">开始播放</button>
<button id="btnReplay">重播</button>
<div class="stage">
  <div id="s-open" class="scene active">…N 个场景分别一个容器…</div>
  …
</div>
<p id="sentence"></p>   <!-- 卡拉OK字幕 -->
```

数据内联（file:// 页面不能 fetch 本地 JSON，必须写死在 JS 里）：

```js
const CHARS = ["喽", "，", "大", "家", "好", "。", …];   // 全部字
const TIMES = [1.87, 1.91, 1.95, …, ];                   // 每字开始秒
const SCENES = [["s-open", 0], ["s-pgpr", 16.43], …, ];  // 场景 id + 开始秒
```

逐帧录制（环境要求：已安装 playwright 的 Python 解释器）——打开页面 → 点击播放 → 逐帧 seek + 截图：

```bash
python scripts/render.py <html路径> <输出帧目录> <时长秒> [fps] [start] [stop]
```

- 参数：帧率 20、时长 113.2、模式 full。
- 输出：`frames/f00000.jpg … f02263.jpg`（1080×1920 竖屏）。
- 20fps × 113s ≈ 2260 帧，全程约 10 分钟。

FFmpeg 合成：

```
ffmpeg -framerate 20 -i frames/f%05d.jpg -i assets/voice.wav \
  -c:v libx264 -pix_fmt yuv420p -crf 18 -c:a aac -b:a 192k -shortest 输出.mp4
```

- `-pix_fmt yuv420p` 保证抖音 / 手机可播；`-shortest` 对齐到音频结束。

## 8. 抖音爆款视觉留存规范（N0003 复盘沉淀 · 每片必用）

### 8.1 开场钩子（0~3s 决定完播）
- **首屏放"全片最吸引人的信息点"**（钩子），不放纯品牌名/纯标题：反差数字（"100 块肥料真正吸收的不到 20 块"）、悬念提问（"一株菌怎么帮作物防病？"）、痛点场景、强利益点；品牌名/标题作辅助元素。
- 钩子动效组合：大字 scale 0.8→1 + 扫光 + 粒子爆发（0.4~0.6s 完成），首字出声前完成冲击。
- 钩子文案来自文案首段或全片提炼，时间点仍用时间戳首字对齐。
- **无回顾内容时不强做回顾段**：文案直奔主题就直奔主题（形态 B），有回顾才做回顾（形态 C），详见第 3 节。

### 8.2 波次入场动效（消灭"一次性静态呈现"）
- 每个场景切进后，元素按 **2~3 波** 入场：
  - 第 1 波（0s）：badge（场景内徽标，如"第一个·直接杀菌"）弹入（scale 0.9→1 + fade，0.3s）；
  - 第 2 波（+0.15s）：h2 标题 + sub 副题 淡入上浮（translateY 20px→0）；
  - 第 3 波（+0.3s 起）：卡片/数据 stagger 上浮，每项间隔 0.08~0.12s。
- 实现：CSS 场景激活时加 `.in` class，子元素 `transition-delay` 逐项递增；或 keyframes + `animation-delay`。
- **关键数字/词条持续强调**：讲解到该数据时画面元素同步高亮/放大（scale 1→1.08 呼吸循环），字幕-画面联动。

### 8.3 转场动效（场景切换必须"有反应"）
- 场景切换：旧场景 0.25s 淡出 → 新场景 0.45s 淡入 + 入场波次。
- 加闪光转场：`flash` 元素在切换瞬间闪一次（opacity 0→0.35→0，0.25s）。**注意坑 #20**：flash 触发条件不要写成恒 false 的死逻辑（`curScene` 已被赋新值后再比较）。
- 避免生硬硬切；每处切换都应有 1 个可感知的视觉事件。

### 8.4 结尾留存（CTA 不静态）
- CTA 四按钮（点赞/关注/收藏/评论）弹入（stagger 0.06s）+ 循环脉冲（scale 1→1.06，2s 周期）。
- 结尾内容按文案实际结尾设计：有"下期预告"时用钩子短句（如"给土壤解毒"）放大呈现；无下期预告时用总结金句或利益点回扣（如"少花冤枉钱，肥料吸收率是关键"）。
- 关注引导文案按需追加（如"关注不迷路，下期更精彩"）——非系列/一次性内容可不加。

### 8.5 音效点缀（成片不能只有人声）
- 三类音效：转场 whoosh（场景切换）、数字强调 pop（关键数据出现）、结尾 chime。
- 实现：**独立音效轨 + FFmpeg amix**——
  1. ffmpeg 合成短音效 WAV：`ffmpeg -f lavfi -i "sine=frequency=880:duration=0.15" pop.wav`（whoosh 可用 noise 滤波，chime 可用多正弦叠加）；
  2. 按时间戳（场景边界/数据出现点）用 ffmpeg adelay 拼接成一条 sfx 轨（长度 = 配音时长）；
  3. 合成命令追加：`-i sfx.wav -filter_complex "[1:a][3:a]amix=inputs=2:duration=first"`。
- HTML 内不播音效（录制时 seek 静音不可靠，播放不触发）。

### 8.6 节奏与信息密度
- 视觉节奏：每 2~3 秒画面必须有变化（波次入场、数据强调、转场、字幕推进都算）。长片后段（>60s）最容易疲劳，靠数字强调 + 场景变化撑住。
- 张弛有度：信息密度高的场景（如 S7 诱导抗性）控制为 3 波以内，不堆叠；密度低的场景（如 S5 广谱抑菌）补一行总结或计数动效，不留大空白。
- 每屏视觉焦点只有一个：数字或图形，别让文字堆满全屏。

## 9. 图案与图形化表达规范（画面精美生动 · 消灭"纯文字屏"）

> 目标：每屏都有一个**图形化主视觉**，文字退居配角。全部图案用**内联 SVG + CSS** 手工绘制（file:// 禁止外链图片/字体/外部资源），统一图标风格与主题色。

### 9.1 数据图形化（数字不许裸奔）
- **每个关键数字配一种图形载体**，按语义选型：
  - 占比/百分比（如 5%~8%、近 9 成）→ **环形进度环**（`stroke-dasharray` 按值绘制，中心放数字）或**块状占比格**（10×10 格子点亮 n 格）；
  - 对比/量级（如 A vs B、成本 vs 吸收）→ **双色柱状对比**（两根柱子/两段能量条，不同主色）；
  - 时间/时效（如 96 小时）→ **时间轴**或**倒计时环**；
  - 多数据并列 → **小型条形图/图标矩阵**，不用文字清单。
- 图形与数字同框：数字居中大字（≥8cqw）+ 单位小字 + 图形环抱/衬底，动画用"进度环从 0 画到目标值"（时长 0.6~1s，与讲解到该数据的时间对齐）。
- **禁止**：把"5%~8%"这种数字直接一行文字摆在那里，无图形载体。

### 9.2 概念图示化（禁止纯文字卡片）
- 每个概念/机制配一张**示意图**，按内容形态选：
  - 流程/机制（如插入细胞膜→形成孔道→物质外泄）→ **SVG 流程链**：图标节点 + 连接线 + 箭头，线用 `stroke-dashoffset` 画线动画依次点亮节点；
  - 分类/清单（如四类抗菌物质）→ **图标网格**：每个条目 = 图标 + 词条，图标承载主要视觉；
  - 结构/组成（如基因组占比）→ **分层环形/同心圆**；
  - 路径/通路（如信号通路）→ **节点连线图**（节点圆 + 箭头 + 流光线）。
- 图标绘制原则：线性风格统一（`stroke-width:1.8`、`fill:none`、`stroke:currentColor`），圆角一致，同一场景图标保持同一尺寸网格；每个图标 1 个主题色 + 主色高亮 1 处。

### 9.3 视觉隐喻（抽象概念用具象物表达）
- 把抽象功能映射到**观众熟悉的具象物**，用 SVG 画出，比文字强 10 倍：
  - "武器库/直接杀菌" → 盾牌 + 子弹/炮塔 + 靶心；
  - "给植物打疫苗" → 针筒 + 盾牌 + 植物；
  - "抢地盘/空间竞争" → 方格棋盘（病原菌 vs 益生菌占位对比）；
  - "饿死病原菌" → 铁离子被吸走、病原菌萎缩的对比图；
  - "合成工厂" → 厂房 + 流水线 + 输送带；
  - "让植物战备" → 植物亮起防护罩/盾牌光环。
- 隐喻物本身要有动效：盾牌脉冲、针筒下落、棋盘格子依次点亮、流水线小件移动。

### 9.4 背景与氛围（场景不是白板）
- 每场景背景必须有**氛围层**（区别于主内容层）：主题色径向渐变底 + 大号几何装饰（圆环/网格/光斑/叶子剪影，低透明度 0.06~0.12）+ 粒子/漂浮物循环动画。
- 场景间氛围可微变：换主色渐变角度或装饰图形（如 S1 绿光、S5 红光警告、S7 紫色科技感），制造"换场感"而不依赖闪屏。
- 背景层 `pointer-events:none`，保证不挡文字与图标。

### 9.5 循环动效库（让画面"活"起来）
| 动效 | 用途 | 实现 |
|---|---|---|
| 浮动 float | 图标/装饰物缓慢上下 | `translateY 0→-8px` 2.5s ease-in-out infinite alternate |
| 呼吸 breathe | 关键数字/主图形 | `scale 1→1.06` 1.8s infinite alternate |
| 旋转扫描 | 圆形徽标/光环 | `rotate` 8s linear infinite |
| 流光 sweep | 标题/卡片描边高光 | 渐变背景 `background-position` 扫过 2s |
| 描边画线 | 流程线/进度环 | `stroke-dashoffset` 一次性（对齐讲解时间点） |
| 脉冲扩散 pulse | 攻击/命中/强调 | `scale 1→1.5 + opacity 1→0` 1.2s infinite |
| 粒子漂移 | 背景氛围 | canvas 粒子（已有 bg-canvas，可加主题色粒子） |
- 动效纪律：同一屏不超过 2 种循环动效（1 主 + 1 辅），避免眼花；`prefers-reduced-motion` 时降为静态完整状态。

### 9.6 布局层次（图形是主角，文字是配角）
- 每屏视觉层级：**主视觉图形（最大、最亮、中心/偏上）→ 标题 → 说明短句**；文字行数 ≤2 行/屏（不含字幕）。
- 图形与文字分区：图形占 45%~60% 画面（中上部），文字区在图形下方或侧面，不叠加。
- 卡片化：需要文字分组时用半透明卡片（`background:rgba(255,255,255,.06)` + `border:1px solid rgba(255,255,255,.14)` + 圆角 16px），卡片本身带浮起/压入微动效。
