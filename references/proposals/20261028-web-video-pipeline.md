# 网页视频分阶段制作系统：重构提案

日期：2026-10-28。状态：设计提案，未接入现有生产命令；不修改旧作品、现行Skill或发布授权。

## 目标

输入作品文案、原声及用户提供的识别结果/字时间戳，逐步产出可检查的镜头、视觉设计、素材、单镜头网页及完整网页视频。不以PPT或六种版式作为创作边界。

标准化输入输出、时间、质量与交付边界；视觉表达按内容选择。保留一键串联，但任何阶段都必须可独立查看、复跑与比较，不要求用户逐步手工批准。

## 用户四步与补充环节

0. 素材核验、全片视觉基调：原件登记、对齐检查、画幅、字幕/HUD/控件偏好、字体/配色/背景、素材取得策略。先确定共用风格，再扩展逐镜画面。
1. 语义镜头拆分：根据讲解逻辑和原始时间戳划分镜头；每镜定义目标、原文范围、关键口播节拍及切点依据。
2. 逐镜视觉扩展：编写可执行的画面设计说明，形成静态草图或联系表；扩展视觉表达，不新增未经支持的科学事实、数据或口播。
3. 实现规划与单镜头制作：选择表现方式与素材、准备资产、编排动效，产出独立可播放镜头；允许返回第二步修改设计。
4. 全片组装：镜头编排到统一时间轴，合成原声、字幕、背景、转场、音效、HUD及播放控件。
5. 分层检查与返工：每步检查本步产物，最终检查连续观看、同步和跨镜一致性；将问题指向原始产生步骤。

## 分阶段契约

以下文件名和命令均为拟新增接口，不代表已经实现。

| 阶段 | 输入 | 输出 | 可见预览 | 检查 |
|---|---|---|---|---|
| intake | 文案/音频/识别结果 | source-map.json、style-guide.json | 对齐差异、共用风格样本 | 原件哈希、时间合法、识别/原文差异 |
| segment | source-map | shots.json、shots.md | 原文范围、波形/时间轴、切点 | 原文覆盖、术语/数字完整、时长及切点 |
| direct | shots、style-guide | visual-briefs.json | 静态关键帧/草图联系表 | 重点、信息层级、表达依据、跨镜重复 |
| produce | brief、能力与素材目录 | implementation.json、assets、scene spec | 单镜头预览、关键帧、素材对照 | 真实能力、素材可用、字形/几何/动效与同步 |
| assemble | 单镜头场景描述与验证记录 | timeline.json、完整index.html/工程 | 整片时间轴、连续播放 | 全局偏移、转场、字幕、声音、seek/重播 |
| review | 所有阶段与实际预览 | stage-report、整体报告 | 问题定位、A/B版本对照 | 自动错误与语义/审美/听感分开记录 |

每个镜头可独立产出single-scene.html，但合成输入是同一渲染器消费的场景描述及素材，不拼接iframe、不重复嵌入多套播放器，也不把预览视频二次编码成最终网页。

## 第一阶段：分镜Skill

- 原文是语义依据，原声是物理时钟；识别结果可用于定位，但不能静默改写原文或假称转写准确。
- 在对齐差异中明确字符替换、缺失、重复、异常时间及低置信区间。能自动确定的差异可映射修正，原识别文件保持原件，不能虚构对应关系。
- 先辨认主题、因果、对照、枚举、转折、结论，再选择镜头边界。不能按句号、固定秒数或关键词直接决定最终镜头/视觉。
- 镜头包含一个明确观看目标，可有多个信息节拍；一个句子不等于一个镜头，一个镜头也不等于一页。
- 绑定sourceSpan、原字符索引/稳定ID、原词及解析后的整数微秒；重复词明确身份。保留现有原词occurrence能力。
- 核对原文覆盖不漏不重；画面时间轴连续覆盖原声，静音段可保留/延续相邻镜头，不通过改写音频填平。
- 页长/节拍阈值在新模式中作为可解释的诊断项；不能不经迁移就复制旧4–20秒为通用硬规则。硬性边界与建议范围分开。

## 第二阶段：视觉设计说明

不要仅追求提示词长度。每镜至少描述：

- 对应原文与观看目标：观众应理解或记住什么。
- 表达关系：重点、并列、对照、因果、空间、递进等。
- 主体/辅助元素与层级：文字、图像、图形各承担什么信息。
- 构图、视觉焦点、留白与字幕避让；继承共用风格，允许局部变化。
- 时间顺序：开始画面、关键口播事件、强调/替换及结尾保留画面。
- 需要的素材、科学适切性、不得展示或虚构的内容。
- 静态关键帧及与相邻镜头的差异、必要的连续性。

通用视觉说明与工具专用prompt分离。搜图词、生图prompt、SVG绘制说明和动效指令由第三阶段分别生成，不能同一长段文字直接投给所有工具。

## 第三阶段：实现方式是三条独立轴

| 轴 | 可选方式 |
|---|---|
| 素材来源 | 用户/本地、项目内置、联网检索、生成服务、代码绘制 |
| 素材格式 | 文本、矢量/SVG、普通位图、透明位图（后续可按需求扩展视频） |
| 呈现方式 | 排版、裁切/镜头移动、分层合成、路径显现、重点标记、关系展开等 |

同镜头可以：搜到的照片做局部背景、透明主体图叠加、SVG箭头表达关系、原生文字随口播出现。不能把混合方式当互斥模板。

实现规划记录元素级选择、理由、使用能力、资产需求、替代方案和状态。工具缺失、费用/上传未授权、素材许可不清、能力未实现都明确记录，不能静默降级成矩形卡片。

素材完成后验证真实尺寸/解码/透明通道与焦点、来源/许可、哈希及科学语义。网页运行不依赖外部图片URL；取得后本地登记。

当前asset-import只接受PNG/JPEG/WebP，尚无SVG制作链路。新增SVG时须设计受限SVG子集（禁止脚本、外链和foreignObject等）、字体处理、资源预算，以及预览/导出的同源表现。完整SVG可作为静态资产；逐元素动画需要元素ID/分层或转成场景节点，不能把整张SVG导入称为已支持其内部动画。

编译失败时返回具体能力缺口或容量拆分建议；受控组件可组合，不再只开放六种页面。自定义效果通过开发者维护的确定性组件扩展并回归，普通生产不附加任意脚本或CSS。

## Skill结构

保留一个总入口Skill，路由到四个阶段Skill：

1. shot-planning：原文/原声对齐、语义拆镜与信息节拍。
2. visual-direction：共用风格与逐镜视觉说明/草图。
3. scene-production：实现选型、素材工作流、动效与单镜头预览。
4. video-assembly：全片时间轴、字幕/声音/背景、整体检查与交付。

每个Skill只定义本阶段职责、输入输出、工具入口、判断依据和失败/返工条件。数值门槛由共享契约和Profile维护；可执行能力从能力目录读取，不能靠Skill声明功能存在。规则不复制四份。统一执行器验证产物，防止换Agent后跳步；单Agent也能完成全流程，不强制多Agent。

当前Skill的PPT定位、固定六类版式及默认总是选择文字兜底需在新模式中重写；原文保真、时间身份、资产登记、字形/安全区/净空、背景、HUD/控件及签名边界保留并按场景适用。

## 去除黑盒的工程要求

- 所有阶段落盘版本化产物及简短决策依据、来源ID、工具执行结果；不保存私密密钥或模型隐式推理。
- 输入指纹绑定产物；上游变更将依赖产物标为stale，禁止误用旧结果。
- 阶段状态：pending/running/ready/blocked/stale；自动通过与独立批准分开。
- 支持指定阶段/指定镜头复跑、恢复与A/B对比，未受影响的镜头复用；复用依据包括输入/工具/模型/配置版本。
- 失败写明步骤、镜头、缺失项、可修复路径及尝试记录；已完成产物保留，外部付费动作不盲目重试。
- 一个制作过程HTML入口：原文/时间轴、分镜表、视觉说明/草图、素材、单镜头预览、整片、检查报告。可先生成静态只读入口，再按需要加编辑服务。
- 可自动串联，不新增每步必须人工点通过的流程；无法判断的审美/听感仍如实待复核。

建议CLI（拟实现）：

```text
vibe pipeline intake <inputs>
vibe pipeline segment <project>
vibe pipeline direct <project>
vibe pipeline produce <project> --shot <id>
vibe pipeline assemble <project>
vibe pipeline inspect <project>
vibe pipeline run <project> --from <stage>
```

## 现有项目的取舍

保留：音频/字时间处理、原词锚点、字幕、素材登记、确定性共享渲染器、背景模块、固定HTML播放器、质量证据/签名、导出消费协议。

重构：前端创作模型与阶段执行器、故事/视觉说明/实现计划的独立Schema、场景组合能力、素材能力协商、阶段检查与过程预览。

现有story v1/v2继续解析，旧编译器保留旧路径；新的制作中间格式单独版本化，不把旧故事自动扩写。六类版式可作为可选组件预设，不再是顶层创作上限。scripts/build_presentation_examples.py是测试/示例工具，不能担任正式导演。scripts/storyboard.py的标点/时长/关键词拆分只能提供候选，不作为新语义分镜Skill的替代品。

本轮不因重构而立即替换所有渲染技术或改WeMediaForge正式发布行为；若新组件需要共享能力，维护上游、升级真实版本/指纹、同步两端与消费契约回归。

## 实施顺序与验收

1. 基线与接口：保存当前代码/产物边界，拟定新阶段Schema及状态/依赖模型；明确硬约束和创作建议。旧路径回归保持。
2. 可见流程贯通：实现intake/segment/direct产物、分镜Skill与静态过程预览；用N0009核验原文覆盖和真实时间，无需重做整片。
3. 三个代表镜头：重点表达、关系解释、混合素材。先比较视觉草图，再完成素材和单镜头；至少验证可组合原生文字/图形、受控SVG、透明位图和本地素材。搜图/生图真实工具调用视授权与环境单独记录。
4. 组装贯通：统一场景时间和资产索引，字幕/原声/背景/控件接入；组装消费的是已验证场景描述，避免重新生成造成单镜头与整片不一致。
5. 全片迁移：三个样片与过程链路评估有效后，生成N0009新版本；现有v18与历史作品保持。
6. 跨Agent验收：Skill路由、阶段产物复用、指定镜头返工、失效传播、原始资料保真、错误定位及旧/新生产消费回归。

完成标准：可从三份输入逐步得到可查看产物；任何镜头均能追溯原文与时间、视觉说明、资产来源、实现选择和检查结果；只改一镜可局部重做；单镜头与整片同时间点一致；静态/动画/手机/音频与消费回归通过。审美、科学语义、听感与发布签名保持真实观察边界。
